1. Реляционная модель (3-я нормальная форма — 3NF)

Структура операционной базы данных реляционного уровня:

erDiagram
    client {
        int client_id PK
        string full_name
        string phone UK
        string email UK
        text address
    }
    movie {
        int movie_id PK
        string title
        string genre
        int release_year
        numeric rental_rate
    }
    employee {
        int employee_id PK
        string full_name
        string phone UK
        string position
    }
    rental {
        int rental_id PK
        timestamp rental_date
        date due_date
        date return_date
        string status
        int client_id FK
        int employee_id FK
    }
    rental_item {
        int rental_id PK, FK
        int movie_id PK, FK
        numeric fee
    }

    client ||--o{ rental : "оформляет"
    employee ||--o{ rental : "обрабатывает"
    rental ||--|{ rental_item : "содержит"
    movie ||--o{ rental_item : "включается"

Таблицы схемы 3nf:

ТаблицаОписание
clientСправочник клиентов видеопроката
movieКаталог доступных фильмов
employeeСотрудники пункта проката
rentalЖурнал заказов (аренды) фильмов
rental_itemПозиции заказа (какие фильмы взяли)

2. Модель Data Vault 2.0 (Хранилище данных)

Архитектура хранилища сырых данных (Хабы, Ссылки, Сателлиты):

erDiagram
    hub_client {
        uuid client_hkey PK
        string client_bk UK
        timestamp load_date
        string record_source
    }
    sat_client {
        uuid client_hkey PK, FK
        string full_name
        string email
        text address
        timestamp load_date PK
        string record_source
    }
    hub_movie {
        uuid movie_hkey PK
        string movie_bk UK
        timestamp load_date
        string record_source
    }
    sat_movie {
        uuid movie_hkey PK, FK
        string title
        string genre
        int release_year
        numeric rental_rate
        timestamp load_date PK
        string record_source
    }
    hub_employee {
        uuid employee_hkey PK
        string employee_bk UK
        timestamp load_date
        string record_source
    }
    sat_employee {
        uuid employee_hkey PK, FK
        string full_name
        string position
        timestamp load_date PK
        string record_source
    }
    hub_rental {
        uuid rental_hkey PK
        string rental_bk UK
        timestamp load_date
        string record_source
    }
    sat_rental {
        uuid rental_hkey PK, FK
        timestamp rental_date
        date due_date
        date return_date
        string status
        timestamp load_date PK
        string record_source
    }
    link_rental_client {
        uuid link_rental_client_hkey PK
        uuid rental_hkey FK
        uuid client_hkey FK
        timestamp load_date
        string record_source
    }
    link_rental_movie {
        uuid link_rental_movie_hkey PK
        uuid rental_hkey FK
        uuid movie_hkey FK
        timestamp load_date
        string record_source
    }
    sat_rental_movie {
        uuid link_rental_movie_hkey PK, FK
        numeric fee
        timestamp load_date PK
        string record_source
    }

    hub_client ||--o{ sat_client : "sat"
    hub_movie ||--o{ sat_movie : "sat"
    hub_employee ||--o{ sat_employee : "sat"
    hub_rental ||--o{ sat_rental : "sat"
    hub_rental ||--o{ link_rental_client : "link"
    hub_client ||--o{ link_rental_client : "link"
    hub_rental ||--o{ link_rental_movie : "link"
    hub_movie ||--o{ link_rental_movie : "link"
    link_rental_movie ||--o{ sat_rental_movie : "sat"
